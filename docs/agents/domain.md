# Domain Documentation

This repository uses single-context documentation.

Read root `CONTEXT.md` for responsibility, non-goals, ownership, and domain terms.
Read relevant records under `docs/adr/` when the task touches their decisions.
Use canonical terms from CONTEXT; do not invent additional boundaries.
Surface conflicts with accepted ADRs rather than silently overriding them.

No CONTEXT-MAP or nested context directories are configured.
Create durable decisions only after habit confirms their tradeoffs.
